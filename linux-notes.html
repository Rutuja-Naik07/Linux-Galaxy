Linux notes, from first command to production

Three levels, each one building on the last. Run the commands in a terminal as you read. Folders, permissions and pipes below are interactive.

Beginner

Get comfortable moving around, handling files, and understanding permissions.

What Linux is

Linux is a kernel: the core program that talks to your hardware. A distribution (Ubuntu, Fedora, Debian, Arch) bundles the kernel with tools, a package manager and a desktop. You control it mostly through a shell, such as bash, which reads the commands you type.

The filesystem

Everything hangs off one root, /. There are no drive letters. Click a folder to open it.

Permissions

Each file has read (4), write (2) and execute (1) rights for three groups: owner, group and others. Add the numbers to get one digit per group. Tick the boxes to see the mode.

chmod calculator

chmod 755 script.sh      # owner rwx, others r-x
chmod u+x script.sh      # add execute for owner
chown alice:dev file     # change owner and group

Intermediate

Combine small tools, manage processes and users, and automate with scripts.

Pipes and redirection

Each program does one job. A pipe (|) feeds the output of one into the next.

cat access.loggrep 404sort | uniq -chead
cmd > out.txt     # overwrite file with output
cmd >> out.txt    # append
cmd 2> err.txt    # send errors only
cmd > all.txt 2>&1   # both streams
cmd < in.txt      # read input from a file

Shell scripting

#!/bin/bash
set -euo pipefail          # stop on errors and unset variables
name="${1:-world}"         # first argument, default "world"
for f in *.log; do
  if [ -s "$f" ]; then echo "$f has data"; fi
done
echo "Hello, $name"

Make it runnable with chmod +x script.sh, then run ./script.sh Ana. Always quote variables ("$f") so spaces in names do not break things.

# /etc/systemd/system/app.service
[Unit]
Description=My app
After=network.target
[Service]
ExecStart=/usr/bin/node /srv/app/index.js
Restart=on-failure
User=app
[Install]
WantedBy=multi-user.target

After editing a unit file, run sudo systemctl daemon-reload.

Networking and SSH

ip addr; ip route          # interfaces and routes
ss -tulpn                  # listening ports and owners
curl -I https://example.com
dig example.com; traceroute example.com

ssh-keygen -t ed25519
ssh-copy-id user@host
ssh -L 8080:localhost:80 user@host   # local port forward
sudo ufw allow 22/tcp && sudo ufw enable
Harden SSH: in /etc/ssh/sshd_config set PasswordAuthentication no and PermitRootLogin no, then restart sshd.

Containers under the hood

A container is an ordinary process with limits. Namespaces control what it can see (processes, network, mounts, users). Cgroups control what it can use (CPU, memory, I/O). Try unshare --pid --fork --mount-proc bash to get a shell that sees only its own processes.

Security checklist

Apply updates automatically, use SSH keys only, run services as non-root users, keep a firewall default-deny, review sudo -l and SUID files with find / -perm -4000 2>/dev/null, and consider SELinux or AppArmor for mandatory access control. Back up with a tested restore, not just a backup.
